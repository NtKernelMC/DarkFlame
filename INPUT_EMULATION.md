# Ввод через PostMessage

`dfEmulateKey(key, pressed)` отправляет сообщения клавиатуры через `PostMessageA`.
`rmb` и `lmb` отправляют сообщения правой и левой кнопки мыши. Прежний
`dfEmulateMouseButton("right"/"left", pressed)` также сохранён.
Возвращаемое `true` означает, что сообщение поставлено в очередь окна; выполнение
действия игрой этим не подтверждается. Ошибка отправки возвращает `false`.

DirectInput-эмуляция и синхронный fallback удалены. SendInput не используется.
Окно берётся из параметров игрового DX9-устройства, проверяется принадлежность
процессу. Резервный поиск по процессу не запрашивает заголовки окон.

Поддерживаются буквы, цифры, Space, Enter, Tab, Esc, Backspace, F1–F24,
стрелки, Insert/Delete/Home/End/PageUp/PageDown, CapsLock/NumLock/ScrollLock,
левые и правые Shift/Ctrl/Alt. Имена клавиатурных клавиш нечувствительны к регистру.
`SHIFT`, `CTRL`, `ALT` выбирают левую клавишу. Модификаторы отправляются с общим
VK-кодом и scan code соответствующей стороны; Ctrl/Alt справа имеют extended bit.
Каждый явный вызов нажатия отправляется без previous-state bit, как в старой
функции: MTA отбрасывает автоповтор. Это позволяет восстановить удержание после
сброса игрового ввода при переключении окна/меню. Отпускание использует scan code
успешного нажатия, даже если раскладка между ними поменялась.

Комбинация задаётся отдельными вызовами: сначала модификаторы, затем основная
клавиша; отпускание — в обратном порядке. Строка `"SHIFT+W"` не является именем
клавиши и не поддерживается.

**Ограничение MTA:** `CKeyBinds::ProcessMessage` игнорирует сообщения `VK_SHIFT`;
Shift обрабатывается отдельным опросом состояния. Чистый PostMessage не обеспечивает
Shift и сочетания с ним в MTA. Проверка приёмником Windows этого не проверяет.
По последнему указанию пользователя управление ЖБК возвращено на игровые контролы,
поэтому его прыжок не зависит от обработки Shift через PostMessage. Источник ограничения:
[CKeyBinds.cpp](https://github.com/multitheftauto/mtasa-blue/blob/master/Client/core/CKeyBinds.cpp).

```lua
dfEmulateKey("LSHIFT", true)
dfEmulateKey("W", true)
-- Отпустить после нужного интервала, например из существующего таймера:
dfEmulateKey("W", false)
dfEmulateKey("LSHIFT", false)
```

Для мыши сохраняются флаги удерживаемых кнопок и синтетических Shift/Ctrl.
Состояние обновляется только после успешной отправки; неудачное отпускание
можно повторить. Эти флаги не изменяют физическое состояние клавиатуры Windows.
Если игра проверяет Shift через GetKeyState/GetAsyncKeyState, чистый PostMessage
этого не заменяет — [ограничение описано Microsoft](https://devblogs.microsoft.com/oldnewthing/20050530-11/?p=35513).

ЖБК использует прежний `setPedControlState` для forwards/sprint/left/right/jump/fire.
Через `dfEmulateKey("r", ...)` идёт импульс клавиатурной R каждые 2 секунды,
отпускание через 100 мс. При выключении или выгрузке R отпускается; неудачное
отпускание повторяется таймером. Меню/чат приостанавливают импульсы и отпускают R.
Старые настройки Anti-AFK удалены. Логика маршрутов ЖБК восстановлена из f8fa7de.

Проверки: `python -B Tests/pilot_input_test.py` и
`python -B Tests/jbk_controls_test.py`. Native-тест использует отдельные окна
на текущей Windows, проверяет 2000 циклов двери/ПКМ, обе стороны модификаторов,
Shift+W, Ctrl+Shift+W, Alt+W, сочетания мыши, полную очередь и выбор окна.
Проверки всех версий Windows и игровой сессии этим не заменяются.
